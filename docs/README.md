## 文档职责

一个事实只允许有一个持续维护的权威来源：

| 内容 | 唯一真相源 | 其他文档如何引用 |
|---|---|---|
| 产品定位与快速开始 | `README.md` | 只链接，不复制安装步骤 |
| 适配器安装与验证 | `docs/adapters.md` | 示例配置文件保留机器可用模板 |
| 当前实现架构 | `docs/architecture.md` | RFC 只解释决策，不描述每日进度 |
| 当前能力与限制 | `docs/status.md` | README 只保留摘要 |
| 长期工程规则 | `docs/engineering.md` | 历史复盘保留事故证据 |
| 架构决策 | `docs/rfcs/**` | 当前实现文档链接对应 RFC |
| 历史过程 | `docs/InitPrompt.md`、`docs/复盘与工程约定.md` | 不作为当前行为或待办依据 |

当历史文档、RFC 和代码不一致时：

1. “当前行为”以代码及同提交内更新的 `architecture.md`、`status.md` 为准。
2. “为什么这样设计”以已接受的 RFC 为准。
3. 历史文档只说明当时的背景、假设和证据，不自动成为今天的要求。

## 维护规则

1. 改了契约、路径、命令、默认值或平台支持范围，必须在同一提交中更新权威文档。
2. 可变状态只写入 `status.md`；不要在 RFC、历史复盘或多个索引中复制。
3. 未经实测的结论标明“静态审计”或“单元测试”，不要写成端到端已验证。
4. 开放缺陷优先进入 GitHub Issue；文档只保留影响用户理解的限制摘要。
5. 中文正文使用全角标点；代码标识符、配置键、事件名和路径使用反引号。
